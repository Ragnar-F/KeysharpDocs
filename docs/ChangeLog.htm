Recent Changes

This page summarizes the script-visible changes in recent Keysharp releases, so that a script written against an earlier version can be brought up to date. The release page holds the authoritative notes and the downloads for each version.

Note: Keysharp has not reached version 1.0. Behavior can change between releases, including in ways which require edits to existing scripts. Each release below lists its breaking changes first.

0.0.0.17

In development.

Breaking Changes

  • StrPtr of a variable returns the address of memory the variable keeps for native code, as in AutoHotkey, where it returned a StringBuffer for any reference, which wrote back to it, and otherwise the address of a pinned copy which ObjFree had to release. The address stays the same while the variable exists and its value fits. StrPtr copies the variable's value in only when the variable holds a different string than the one last copied in or taken out. What native code writes there reaches the variable, up to the first null character, at VarSetStrCapacity(&Var, -1) or when the variable is next passed as a Str argument; AutoHotkey shows a write which keeps the length at once. A string without memory of its own, such as a literal, is copied to pinned memory, which ObjFree releases. A number raises a TypeError, where it was converted to a string.
  • VarSetStrCapacity makes the variable blank and leaves it a String, as in AutoHotkey, whatever it held, where it kept the contents and turned the variable into a StringBuffer, resized a StringBuffer the variable held, and raised a TypeError for a number. A capacity below -1 raises a ValueError, where the length was returned, and a capacity above 0 for anything without memory of its own, such as a reference to a property, an object with a __Value property or a function's own local variable reached through &%Name%, raises a TypeError.
  • Every reference to a variable is the same VarRef, as in AutoHotkey, where each & made a new VarRef: &x == &x is true, and a property defined on one is seen through the others. This holds for a local, a by-ref parameter's variable, a global, a static, and a variable which another module declares and a module imports directly. Unlike AutoHotkey, a function's own local or static variable reached through &%Name%, an imported variable reached through %Name%, and a variable which one module imports from another and passes on get a new VarRef each time.
  • A naked variable given a literal Str or WStr type in a direct call to DllCall or ComCall is passed as the variable, as in AutoHotkey, and holds its text up to the first null character afterward. The function wrote into the string the variable held, which kept its length and changed every variable and literal sharing it. An AStr argument is input only, in the system ANSI code page, as in AutoHotkey, where a variable passed as &Var received what the function wrote to it, and a value was converted to ASCII.
  • StringBuffer holds UTF-16 only; the "ANSI" encoding option is removed, and a Buffer with StrGet(Buf, "CP0") receives ANSI text. A StringBuffer passed to DllCall as AStr raises a TypeError, where its memory was passed. Its Capacity is the capacity requested, where it was one more: StringBuffer("", 100).Capacity is 100, where it was 101. Without a capacity, it is the larger of 256 and the initial value's length, where an initial value of 256 or more characters gave one more than its length.
  • A closure's dynamic references, ListVars and RegEx callouts reach only the enclosing functions' variables which the closure names, as in AutoHotkey, where every enclosing variable was reachable. A named fat-arrow function's name is a variable of the function holding it, or a function of the script outside any function, as in AutoHotkey, where only the function's own body could use it.
  • A string with anything other than whitespace after its number is not numeric: Number("1L") throws, IsNumber("1.0D") is 0, and "5x" + 1 treats the string as text, where a single trailing character used to be dropped. Mod throws a ZeroDivisionError for a zero divisor instead of an Error, and like Random takes a numeric string as the Integer or Float it spells, where Mod("7.5", 2) was 1 and Random("3") a Float. A_YWeek and FormatTime's YWeek give the ISO 8601 week-numbering year with a two-digit, Monday-based week, so 2024-12-30 is 202501; the year was the calendar year, and FormatTime's week followed the locale's first day and was not padded.
  • RunScript takes separate Async and Callback parameters. A call which passed a callback as the second argument must pass true second and the callback third. Standard input is available to the child, standard error is redirected, and ExitCode and ExitTime return an empty string rather than throwing while the child is running.
  • Values outside documented ranges raise a ValueError instead of being clamped for A_SendLevel, Ks.A_InputLevel, KeyHistory's MaxEvents, SoundBeep's frequency and WinSetTransparent's alpha.
  • #UseHook, #SuspendExempt, #MaxThreadsBuffer and #Persistent reject an argument other than true, false, 1 or 0, where unrecognized text turned #UseHook and #SuspendExempt off and #MaxThreadsBuffer and #Persistent on. #UseHook with no argument forces the hook, as in AutoHotkey, where it did not.
  • Pause with a value other than 1, 0 or -1 raises a ValueError, as in AutoHotkey, where it paused the underlying thread.
  • The standard tray menu has a &Pause Script item before E&xit, as in AutoHotkey, which moves Exit down one position.
  • Mail requires the host and from options, where it defaulted to localhost and to a sender built from the Windows user and machine name. An unrecognized option key raises instead of being sent as a header, and the header key became headers, taking a Map of names and values. A recipient, address, port or attachment which cannot be used is reported rather than silently dropped.
  • The duplicate collection members were removed: Array.MaxIndex, Array.MinIndex, Map.MaxIndex and Map.MinIndex (AutoHotkey defines these only on ComObjArray, which is unaffected).
  • An Array passed to a COM method or property is passed as the object it is, as in AutoHotkey, so the COM object can call its methods and the script gets the same Array back; it was converted to a SafeArray holding a copy of its elements. Use ComObjArray to pass a SafeArray. An Array is still converted where the member's type information declares a SafeArray parameter, and when the COM object rejects the Array with a type mismatch.
  • A boolean, such as true or the result of a comparison, goes to a COM object as the integer 1 or 0, as in AutoHotkey, whether it is an argument, a value assigned to a property or what a ComObjConnect event handler returns; it went as a COM boolean. Pass ComValue(0xB, Value) where a COM boolean is wanted, as when an HTML event is cancelled by returning false. An object which rejects the integer for a parameter its type information declares as a boolean is given a boolean.
  • ObjHasProp was removed. Use HasProp, except that HasProp also consults a primitive's prototype. Obj.OwnPropCount() was removed in favour of the global ObjOwnPropCount, and Ks.Join in favour of Array.Join.
  • A_IsUnicode (always true), A_LoopFileLongPath (an alias of A_LoopFileFullPath), A_Priority and A_UseHook were removed. A_AllowTimers was replaced by A_Thread.AllowTimers. A_OSType moved into the Ks module and must be imported.
  • FileDirName and WinMaximizeAll were removed from the Ks module. For the directory of a path, use SplitPath, with FileFullPath first when the path is relative; to maximize every window, call WinMaximize for each window WinGetList returns.
  • RegExMatchInfoCs was merged into RegExMatchInfo, so both regex engines return the same class. RegExMatchCs stores an empty value on a miss, as RegExMatch does, instead of a match object whose Success was false; Success is gone from both, and Count on a Cs match excludes the overall match, matching AutoHotkey.
  • A value passed where a variable reference is expected must be one: a VarRef, or an object defining __Value (a virtual reference). Anything else — an ordinary object, a string, a number — throws a TypeError naming the parameter, where an object absorbed the output. This applies to every output parameter of a built-in and to a script function's own & parameters. IsSetRef requires a VarRef.
  • The #Assembly* and #HookMutexName directives were removed. Their settings are keys of the new #App block (Title, Name, ConsoleApp, HookMutexName, ...); each removed directive produces a compile-time error naming its replacement key.
  • More Keysharp-only variables moved into the Ks module and must be imported: A_ClipboardTimeout, A_HotIfTimeout, A_InputLevel, A_Persistent, A_LoopKey, A_MaxThreadsBuffer, A_MaxThreadsPerHotkey, A_NewLine and A_PeekFrequency. Assigning one takes an import by name, such as #Import Ks { A_PeekFrequency }.
  • A_IsPersistent is named A_Persistent, and assigning it is the same as calling Persistent: 1 keeps the script running and 0 lets a script with nothing else to do exit.
  • The Keysharp-only assembly-metadata variables were removed, and the App class carries those facts instead: A_AsmTitle, A_AsmDescription, A_AsmConfiguration, A_AsmCompany, A_AsmProduct, A_AsmCopyright, A_AsmTrademark and A_AsmVersion become App.Title, App.Description, App.Configuration, App.Company, App.Product, App.Copyright, App.Trademark and App.Version, with App.Name for the assembly identity. A_CommandLine becomes App.CommandLine. Reach the class with #Import Ks { App }, or with #Import Ks and then Ks.App.
  • A_KeysharpPath was removed. Use A_AhkPath, which it aliased.
  • A_AhkBuildVersion was removed with no replacement. Ks.A_KsVersion reports the engine build, and App.Version the application's own version.
  • A_HasExited was removed, and App.ExitReason != "" reports that an exit is under way. App.ExitReason is set once the OnExit callbacks have run without cancelling the exit: it is empty inside an OnExit callback, as A_HasExited was false there, but already set in the __Delete calls which begin teardown, where A_HasExited was false.
  • An #App key which was never declared reads as an empty string in both compatibility modes, where the removed variables were unset in v2.1 mode; App.Company != "" tests whether a key was declared.
  • The Keysharp-only screen variables A_WorkAreaWidth, A_WorkAreaHeight, A_TotalScreenWidth, A_TotalScreenHeight and A_ScreenScale were removed; the Monitor class carries those facts for every monitor rather than only the primary. Use Monitor.Primary.WorkArea.Width/.Height, Monitor.VirtualScreen.Width/.Height and Monitor.Primary.Scale. With no display attached the work-area replacements raise instead of yielding 0.
  • A_ThreadId was replaced by A_Thread, a Thread object. A_Thread.Id reads what it did.
  • On Linux and macOS, A_AppData and A_AppDataCommon name the platform's own configuration locations instead of the home directory and /usr/share. A_AppData reads $XDG_CONFIG_HOME or ~/.config on Linux and ~/Library/Application Support on macOS; A_AppDataCommon reads $XDG_CONFIG_DIRS or /etc/xdg on Linux and /Library/Application Support on macOS.
  • The AES, CRC32, MD5, SHA1, SHA256, SHA384, SHA512 and SecureRandom functions were removed. Use the Crypt class: Crypt.Hash(Value, "SHA256") replaces SHA256(Value), Crypt.Encrypt and Crypt.Decrypt replace AES, and Crypt.CRC32 and Crypt.SecureRandom replace the other two. Crypt takes a string as UTF-8 unless an encoding is named, where the functions took its UTF-16 bytes.
  • CopyImageToClipboard and IsClipboardEmpty were removed. Use Clipboard.Image and Clipboard.IsEmpty.
  • MonitorFromPoint and MonitorGetScale were removed. Use Monitor.FromPoint and Monitor.Scale. An out-of-range monitor number throws a ValueError instead of selecting the primary monitor.
  • Objects handed to a script name their members in PascalCase: a size is {Width, Height} and a position {X, Y}. The W and H properties of Overlay and Highlight are likewise Width and Height.
  • Ks.JsonEncode and Ks.JsonDecode became Json.Encode and Json.Decode. A JSON null decodes to unset unless NullValue names a stand-in.
  • Assigning unset to a Map element removes it, and reading an absent element raises an UnsetItemError.
  • Exit takes only ExitCode; its thread-identifier parameter was removed. Use the Thread object to end another thread.
  • WinEvent is constructed from the window criteria and reports each event through a callback slot, rather than through a static subscribing method per event. Hook := WinEvent.Active(Callback, WinTitle) becomes Hook := WinEvent(WinTitle), Hook.OnActive := Callback and Hook.Start(), and Exist, NotExist, Move, Minimize, Restore and TitleChange likewise become the slots OnExist, OnNotExist, OnMove, OnMinimize, OnRestore and OnTitleChange; one hook can fill several of them. The Count parameter was removed with the hook's Count property: call Hook.Stop() as the first statement of the callback to handle one event, or count calls in the callback and stop on the last.
  • Image.GetPixelData's BytesPerPixel defaults to 4 (RGBA), matching SetPixelData and Image.FromBuffer, so the three round-trip. A call which relied on the default to get 8-bit grayscale must pass 1 explicitly.
  • A WinEvent is an EventHook. IsActive became InProgress, and EndReason names why a hook is not running. EventType was removed. IsPaused and Pause(NewState) were removed with the global WinEvent.Pause(NewState) and WinEvent.IsPaused: Stop() and Start() take their place, a restarted hook reports only the events after its Start(), and stopping each hook in for Hook in WinEvent.Hooks replaces the global switch. Stop() discards a callback which was queued but had not started.
  • A running WinEvent keeps the script running, where a script with only WinEvent hooks exited at the end of its auto-execute section.
  • In a WinEvent callback, A_EventInfo holds the rectangle of an OnMove or OnCaretMove event as {X, Y, Width, Height}, where WinEvent.Move's had w and h in place of Width and Height. OnActive, OnExist, OnNotExist, OnMinimize, OnRestore and OnTitleChange do not set A_EventInfo, where it held the event time; use the callback's Time parameter.
  • LockRun(LockObject, Callback, Arguments*) was removed. Create a lock with lk := Lock() and hold it with Acquire/Release; the scoped form is ordinary script code. Only a Lock can be locked on.
  • A RealThread worker reports completion through two tasks. Wait() was removed: Await(worker.Terminated) waits for the operating-system thread, and Await(worker.Task) for the entry function's value. ContinueWith(Callback, Arguments*) was removed; write worker.Task.Then(v => RealThread(Callback, Arguments*)). An error in the worker's body is delivered to whoever awaits its Task rather than reported on the worker.
  • The read-only Visible property of Overlay and Highlight is named IsVisible, and the Granted property of the object RequestCapabilities returns is IsGranted.
  • An encoding name which cannot be resolved throws a ValueError instead of being substituted. This applies wherever an encoding is named, including FileEncoding, FileRead, StrGet and StrPut.
  • Parameters whose names were not valid identifiers were renamed so named arguments can address them: Part# to PartNumber, RootDir\Filename to RootDirFilename, ControlID-or-Pos to ControlOrPos and YYYYMMDDHH24MISS to Timestamp. Other built-in parameter names were corrected to match this documentation.
  • FuncObj is no longer a name; the function-object class is Func. InputObject likewise became InputHook.
  • Overlay construction takes either no arguments or a complete X, Y, Width, Height rectangle. Use Overlay.FromImage(Source) to construct one from an image.
  • An Overlay no longer duplicates Image drawing methods. Draw and read through its borrowed Canvas; copy the canvas before transforming or taking ownership of it.
  • Overlay.Update(Source, ...) became SetImage(Source, ...). BeginDraw/EndDraw are replaced by an explicit Present() after drawing, and Redraw passes its callback the replacement canvas rather than the overlay.
  • Image changes: DrawText and MeasureText take SetFont-style Options and FontName; MeasureText returns an object rather than writing ByRef; Opacity became Alpha; and Search, SearchAll and SearchPixel return a match object and take a flat region.
  • RichText is a member of the RichEdit control rather than of every GuiControl, and reading it returns the RTF document it always accepted on assignment, where it used to return the displayed plain text. Use Value for the plain text.
  • The WebBrowser control type is named WebView: MyGui.Add("WebView", Options, URL), MyGui.AddWebView(Options, URL) and the class Gui.WebView, in place of "WebBrowser", AddWebBrowser and Gui.WebBrowser.
  • InputHook.OnMouseMove reports deltas as (Hook, DX, DY) rather than positions.
  • Notifications which are still queued for OnChar, OnKeyDown, OnKeyUp or a mouse callback when an InputHook ends, by Stop or otherwise, are discarded unless the Input has been started again, where they were delivered. OnEnd always runs.
  • Calling a .NET event's add_EventName or remove_EventName accessor raises a MethodError, where it was called as an ordinary method; subscribe with OnEvent.
  • When hiding or destroying the last visible GUI ends the script while no thread is running, as the default close does, OnExit callbacks receive the exit reason Close, as in AutoHotkey, where they received Exit.
  • A critical error passes OnExit callbacks the exit reason Close, as in AutoHotkey, where it passed Critical. When the auto-execute section fails with an unhandled error and Persistent is not in effect, the script exits with the exit reason Error, where it passed Exit.
  • Every built-in which registers a callback checks it when it is given, as AutoHotkey does, where such a callback was accepted and failed at each call. One which cannot take the arguments the site passes raises a ValueError. An object which cannot be called raises a MethodError, and an object is judged by the MinParams, MaxParams and IsVariadic properties it defines. Hotstring, Sort and the method name of a GUI event sink are not checked, as in AutoHotkey.
  • CallbackCreate checks Function as AutoHotkey does: with ParamSpec omitted, its MinParams is the number of parameters, and an object which does not define MinParams raises a PropertyError, where an object other than a function was given 32 parameters; a ParamSpec which Function cannot take, or which is outside 0 to 32, raises a ValueError, where it was accepted or clamped.
  • CallbackCreate returns the callback's address as an Integer, as AutoHotkey does, where it returned a DelegateHolder object holding the address in its Ptr property: cb.Ptr becomes cb. CallbackFree takes that address, and raises a ValueError for an address which is not a live callback, where it ignored any value but a DelegateHolder. DelegateHolder and Prototype are not class names.
  • The AddRemove of OnExit, OnError, OnClipboardChange and a GUI event must be 1, -1 or 0, as in AutoHotkey; another value raises a ValueError, where it counted as 1 or -1.
  • OnExit, OnError, OnClipboardChange, OnMessage or a GUI event given a callback already registered for it keeps it in its place, as in AutoHotkey, where it was added a second time and ran twice. A closure is a callback of its own, as in AutoHotkey, even one made by the same fat arrow as another. OnMessage given a callback already registered for the message takes the new MaxThreads, and keeps its own when MaxThreads is omitted.
  • A value which is not an object, given where a callback is expected, raises the error AutoHotkey raises for it: a ValueError from Sort, from a GUI event registration on a Gui without an event sink, and from HotIf, where each raised a TypeError. A GUI event sink takes a number as a method name, and a number as the Action of Hotkey is no text, so it only changes the options of an existing hotkey. SetTimer with Function omitted outside a timer's thread raises a ValueError, where it did nothing.
  • RegExReplace raises an error for a Replacement which is an object without a Call method, as AutoHotkey does, where it replaced with the object's text.
  • Assigning BeforeHotkeys while an InputHook is in progress raises a ValueError, where it was accepted and left the hook's ordering relative to hotkeys inconsistent.
  • A callback is passed as a function object. SetTimer("MyFunc"), Func("MyFunc") and every other such site raise a TypeError; write SetTimer(MyFunc), or SetTimer(%"MyFunc"%) when the name is known only at run time. Func(Name, Obj) was removed; ObjBindMethod binds a method by name. A Gui built with an event sink takes one of that sink's method names in OnEvent, OnNotify, OnCommand and OnMessage. Hotkey's Action and Hotstring's Replacement do not look a string up as a function.
  • Array.IndexOf throws an IndexError for an out of bounds StartIndex, as FindIndex does; an empty array returns 0.
  • On an empty array, Array.Filter and Array.Map return an empty Array and Array.FindIndex returns 0, whatever StartIndex is, as IndexOf returns 0, where Filter raised a ValueError and FindIndex and Map an IndexError. On a non-empty array, Filter raises a ValueError for a StartIndex of -(Length + 1), as for any other StartIndex whose absolute value exceeds Length, where it returned an empty Array.
  • OwnProps takes no parameters; the undocumented getValues was removed, so OwnProps(false) is an error.
  • OutputDebug takes only Text. Ks.OutputDebugLine takes the clear flag.
  • StartsWith and EndsWith take CaseSense, matching InStr, in place of the inverted-sense ignoreCase.
  • A CLR call returning a .NET Task hands back a Task object rather than a raw CLR value. Its Result does not wait, where Task.Result blocked the thread; Wait() returns whether it finished before the timeout, including failure or cancellation; and the raw CLR surface moved behind Task.ToClr(). Use Await to wait for a value.
  • A script function handed to a CLR API as a callback runs in a thread of its own on the script thread which created it, where it ran on the thread the CLR called it from. A callback invoked from a foreign thread is therefore asynchronous and cannot return a value to the CLR caller; one invoked synchronously, such as a comparer or predicate, is unaffected.
  • A comma written immediately after the name which starts a statement is a syntax error, as in AutoHotkey, whether the name is a function (MsgBox, "a"), a variable (x, y := 2), a member chain (obj.Method, 1), Goto or For. A space before the comma omits the first argument (MsgBox , "a"), and a name which indexes or calls before the comma forms a comma sequence (fn(), x := 4).
  • Only the leftmost target of a class field declaration becomes a property. Every other name assigned in the initializer is a local of the generated __Init, as in AutoHotkey, so a := b := "asdf" gives the instance an a and no b. Such a name was the module variable of that name. A name that is only read reaches the global, and static fields have their own scope in static __Init.
  • A zero-argument call statement continued by a leading comma on the next line calls the function with its first argument omitted, as in AutoHotkey, where it evaluated the name without calling it.
  • A DefineProp descriptor is validated before the property is touched, as in AutoHotkey: it must name at least one of Value, Get, Set and Call; Value cannot accompany the other three; and each of Get, Set and Call must hold a function object. Each failure is a ValueError, where {value: 1, call: fn} defined only the Call. The four are read from the descriptor's own value properties, so Map("value", 7) is rejected, where it defined the property.
  • ParseScript was replaced by ValidateScript, which only parses, as --validate-syntax does, and CompileScript, which compiles in memory, as --validate does. Both return an object with IsValid, Errors and Warnings rather than a string of errors which was blank-unset on success, so if (Errs := ParseScript(Code)) becomes if !(Result := CompileScript(Code)).IsValid, with the messages in Result.Errors.
  • Array.MapTo is named Array.Map, Ks.NormalizeEol is named Ks.ReplaceLineEndings, and the class of the object RunScript returns, ProcessInfo, is named ScriptProcess.
  • Base64Encode and Base64Decode became Base64.Encode and Base64.Decode, matching Json and the new Url. Import the class rather than the two functions: #Import "Ks" { Base64 }.
  • Buffer.ToHex(), Buffer.ToBase64() and Buffer.ToByteArray() were removed. buf.ToHex() is Hex.Encode(buf), buf.ToBase64() is Base64.Encode(buf), and buf.ToByteArray() passed where .NET expects a byte[] is buf.
  • Download pumps while it waits, as AutoHotkey's does, so timers, hotkeys and the GUI stay alive during a download and the wait is an interruption point.
  • A GUI event callback which returns any non-empty value, including 0 or a non-numeric string, prevents the remaining callbacks for that event from being called, as in AutoHotkey, where only a non-zero number did. Returning nothing or "" passes the event to the next callback. This applies to every event registered with OnEvent and to OnCommand.
  • A callback whose thread ends with an error prevents the remaining callbacks for that event from being called, as in AutoHotkey, where the next callback was called. This applies to OnEvent, OnNotify, OnCommand and OnMessage of a GUI or control, and to OnClipboardChange and OnExit, so an OnExit callback which fails lets the exit go ahead, where a later callback could cancel it. A callback which calls Exit ends only itself, and the next callback is called.
  • A global OnMessage callback which returns any non-empty value, including 0 or a non-numeric string, claims the message, as in AutoHotkey, where only a non-zero number did: the remaining callbacks for the message are not called, the message is not processed any further, and its reply is the value converted to an integer, which is 0 for a string such as "abc". Returning nothing or "" passes the message to the next callback, and so does a callback whose thread ends with an error or calls Exit. A posted message numbered above 0x0311 can be claimed the same way while the script is interruptible, where it could not be claimed. For one which arrives while the script is uninterruptible, a non-empty return only stops the remaining callbacks, and a callback already running its MaxThreads threads is skipped, where each callback was called.
  • An OnError callback which calls Exit ends only itself, as in AutoHotkey: the next callback is called, and the default error dialog is shown unless one of them returns non-zero, where the Exit skipped the remaining callbacks and the dialog and ended the thread. An error raised while the callbacks run, by one of them or by a thread which interrupts one, shows the default dialog without calling them again, where it called them anew.
  • An OSError raised by a built-in function is a continuable error, as in AutoHotkey: OnError callbacks receive the mode Return, where they received ExitThread, one which returns a negative number lets the thread continue, and the default error dialog offers to continue.
  • An error nothing catches reaches OnError and the default error dialog at the point it is raised, before a Finally block runs, as in AutoHotkey, where a value thrown by the script reached them only once it ended the thread. One which passes a Try statement with a Catch, because no Catch matches it or one re-throws it, reaches them in mode Exit as soon as that statement's Finally block has run, where a built-in error raised there reached them at once. A built-in error's Stack, Line and What identify the failing call before OnError runs. An exception which is not a Keysharp error, such as one thrown by #CSharp code, reaches them when it ends the thread.
  • A class declared in one module resolves through a dynamic reference in another, such as %"MyClass"%, only when that module imports it, as in AutoHotkey, where it resolved in every module. Import it with #Import Other { MyClass }, or reach it as Other.MyClass.
  • A class of the KS module, or the module itself, resolves through a dynamic reference such as %"HashMap"% or %"Ks"% only in a module which imports that name, where it resolved in every module. The KS module is not part of the AHK module, so AHK.HashMap is undefined, where it was the class. Import the name with #Import Ks { HashMap } or #Import Ks, or reach the class as Ks.HashMap.
  • The base class of a class definition resolves as any name in the module does, so a class of the KS module is extended only where it is imported, where any Keysharp class could be extended by its short name or through Ks, nested ones included. class MyMap extends HashMap takes #Import Ks { HashMap }, class MyMap extends Ks.HashMap takes #Import Ks, and a nested class is named through its outer class, as in Gui.Custom. A base class which does not resolve fails the script's load with Invalid base class.
  • A module object has only the module's own globals, functions and classes and the names it imports, as in AutoHotkey, where it answered for every built-in too. Other.MsgBox, Other.Array, Other.A_Index and Ks.MsgBox raise a PropertyError; name the built-in directly, or through the AHK module as AHK.MsgBox. Calling a name the module object lacks raises a MethodError, and assigning one raises a PropertyError, where assigning was ignored or set the built-in variable of that name.
  • The name of a built-in module reaches a script only through #Import, as in AutoHotkey. Ks and Ahk were global names in every module, as any built-in class was, and members of the AHK module; they are neither, so Ks.App takes #Import Ks.
  • Type returns "Module" for every module object, as in AutoHotkey, where it returned the module's name. Through a module object, reading a global which holds no value raises an UnsetError, even under ??, and assigning a function, class or module which the module declares or imports raises an Error, where it replaced a script module's function. Assigning a built-in function or class through the AHK module raises the same error.
  • A module object has no __Item, as in AutoHotkey, so Other["Name"], Other["Name"] := Value and Other["Name", Index] raise a PropertyError, where they read, assigned or indexed the member Name. Write Other.%"Name"% instead. String of a module object calls the ToString function the module declares, and raises a MethodError when it declares none, where it returned the name of the object's .NET type.
  • A name which a function declares global is the variable of its module, so no wildcard import supplies it, as in AutoHotkey: after #Import Ks { * }, global A_PeekFrequency in a function declares the module's own variable, unset until assigned, where the name read the KS module's A_PeekFrequency.
  • A struct class extends only another struct class, and a class defined with class cannot extend one, as in AutoHotkey. Either fails the script's load with Invalid base class, where class Item extends MyStruct and struct Item extends Object compiled.
  • In a function or class body with its own wildcard import, a Keysharp extension, a name the body assigns is its own variable, as a name a module assigns is the module's: a local of the function, or of __Init for a name a field initializer assigns other than the field, and %name% reaches that local too. Such an assignment wrote to the imported variable, or failed to load for a name of a built-in module. Writing to the imported variable takes an explicit import, such as #Import Other { Counter } or #Import Ks { A_PeekFrequency }. A closure likewise reads a name its enclosing function declares global as that global, where the function's wildcard import supplied it.
  • A dynamic reference raises where AutoHotkey does: reading a variable with no value raises an UnsetError, where it yielded an empty string; a blank name, or one which resolves to nothing, raises an error; and in a function, assigning a global through %name% requires a global declaration or an assume-global function, where it assigned the global. Assigning a read-only built-in variable, function, class or module through %name% raises, and &%name% refers to the variable the name finds when the reference is taken.
  • Assigning, or taking a reference to, a function or class which the module declares or imports, an imported module, or a built-in variable which cannot be assigned, such as A_ScriptDir, fails the script's load with AutoHotkey's message, such as This Func cannot be assigned a value: MyFunc, where it replaced the function or imported name. A function's local variable of the same name is unaffected, while assigning a function nested in it fails the same way. MyFunc ??= Value assigns nothing and raises no error, as in AutoHotkey.
  • A variable which a module declares or assigns hides the built-in function or class of its name in that module and has no value until it is assigned, as in AutoHotkey, where it started out holding the built-in. After StrLen := 5 in a module, StrLen and %"StrLen"% are that variable there, even before the assignment, and AHK.StrLen reaches the function. A name the module only reads is the built-in.
  • An #Import in a function or class body, a Keysharp extension, names a module, as one at module scope does, so #Import Array there fails the script's load with #Import: module not found: Array, where it was accepted.
  • Standalone export declarations and default exports were removed, as in AutoHotkey v2.1-alpha.31. A module exports every global variable, function and class, a global which one of its functions declares included.
  • Throw without a value, the statement and the function alike, rethrows the error an active Catch handles, and elsewhere raises the continuable Error("An exception was thrown."), where it threw Error("Error"). Error given an object as Message has an empty message, where the message was the object's string form.
  • A nested function resolves names as in AutoHotkey. One nested in an assume-global function is assume-global too, unless it is assume-static, so a name it assigns is global, where it was a local of the nested function; a name an enclosing function declares global is that global in the nested function, and a static of an enclosing function is that static, where assigning either made a local. x++ and x-- assign x, so they alone make it a local of a function, where they changed the global of that name.

New

  • Image vector drawing adds reusable paths, linear and radial gradient brushes, affine drawing state, intersecting path clips, and state snapshots. Existing shape, text and image drawing follows the same transform and clip.
  • The Http class sends HTTP requests on every platform, through static shortcuts such as Http.Get or a session carrying default headers, credentials and cookies, with an Async form of each method returning a Task.
  • The Url class percent-encodes and decodes text for URLs and form bodies, so a query string is "?q=" Url.Encode(Query).
  • The #App directive declares a script's application facts in object-literal blocks: assembly identity and metadata, Icon, GuiTheme, ConsoleApp, HookMutexName, Linux DesktopEntry and embedded Files.

  • Named arguments: an argument can name the parameter it is for, as in SubStr(s, StartingPos: 2). A name matching no parameter is an error, reported before the script runs where it can be (#Warn NamedArg). NamedArgs carries such a call's names at run time.
  • Operator overloading allows classes and structs to define how operators act on their instances or class objects, including truth tests and increment/decrement.
  • #Warn Experimental reports a compiler warning for imports resolving to the experimental Image, Audio, Monitor, Clr and Overlay classes. Off by default; #Warn All enables it. These APIs may change or be removed without deprecation.
  • Func.Params describes a function's parameters, each as an object with Name, Index, IsOptional, IsByRef and IsVariadic, and Default when the parameter has one.
  • Await and the Task class let a script wait for and chain asynchronous work, such as a .NET API's: Await pumps everything else while it waits, Then chains a continuation, WhenAll and WhenAny combine tasks, Task.Create turns a callback-shaped event into a task, and an object can be awaited through __Await().
  • RealThread.Post returns a Task carrying the queued work's result, and RealThread.Exit returns the task which completes when the worker has ended, so Await(worker.Exit()) stops a worker and waits for it.
  • Support for keys which send a combination rather than one keystroke, such as the Copilot and Office keys. Copilot is an alias in static hotkey and remap declarations for the combination the key emits; it is not a runtime key name.
  • Both terms of a custom combination may carry modifiers, as in <^a & b::.
  • Crypt.Hmac returns keyed SHA digests as hexadecimal. Hex.Encode and Decode convert between hexadecimal text and bytes. Base32.Encode and Decode handle RFC 4648 text and unpadded TOTP secrets.
  • ListView.SetRowColor, SetCellColor and ClearColors control row and cell colors. Structural edits and sorting clear assignments.
  • The Crypt class hashes values and files, encrypts and decrypts with AES, derives keys with PBKDF2 and returns secure random values.
  • The Clipboard class reads and writes the clipboard as text, images, files, HTML, RTF or a native format, and can wait or watch for changes.
  • The Monitor class describes one display: its geometry, identity, scale, brightness and DDC/CI controls, with OnChange for configuration changes.
  • The Audio class plays and records sound, operates devices and other applications' sessions, meters levels, and reports device changes through OnDeviceChange. The Linux and macOS backends are unverified.
  • The Lock class guards code shared between real threads. Acquire takes a timeout and reports whether it got the lock.
  • Thread is a class as well as a function; an instance describes one script thread, can end it, and gives the code it exited with. A_Thread is the current one, A_RealThread the real thread it runs on.
  • The Boolean type names a truth value, so a boolean can be told apart from the Integer 1 or 0 in a type test.
  • The Font class carries a font as a value object, plus the platform's own interface, emoji and monospace families. Gui and each control expose it as a property.
  • The #CSharp directive embeds C# compiled into the script's own assembly: an inline block, a named file, or a <Library> resolved through the Lib folders.
  • NuGet packages, through the #Package directive at compile time or Clr.LoadPackage at run time.
  • The #Warning directive reports a message at compile time without failing the build, as the sibling of #Error.
  • IsComponentAvailable reports whether the parser or compiler component is installed and loadable.
  • Gui.OnMessage and Gui.Control.OnMessage register a callback for a window message. The registration never fires on Linux and macOS.
  • SoundPlay and SoundBeep play on Linux and macOS as well as Windows. Which formats work on Linux depends on the installed player.

  • The WebView control shows a webpage and lets a script drive it: Url, DocumentTitle, history through GoBack/GoForward, Stop, Reload, ExecuteScript and its asynchronous form, LoadHtml and ShowPrintDialog. The page drives the script back through MessageReceived, and five other events report navigation, one of which can cancel it. The rendering engine is not shipped with Keysharp and differs by platform. Engine reports which one a control got.

SetFormat and GetFormat give a range a font, a text color and a background, leaving alone anything the options do not name; BeginUpdate/EndUpdate wrap a whole re-highlight into one repaint. It also has selection, caret, line and position, editing, paragraph-formatting and file members, and the Change, SelectionChange and LinkClick events. Not all of it is available off Windows.

  • The Taskbar class draws a badge and a progress bar on a window's taskbar button, launcher icon or dock tile.
  • Gui.SetIcon and the Icon property give one window an icon of its own, in place of the tray icon it was created with.
  • Gui +DPIResize re-lays a window out when it moves to a display with a different DPI, and +Round rounds its corners. The Menu item options Radio, Right, RTL, Break and BarBreak are supported.
  • Json.Encode takes an Indent option, and Json.Decode a CaseSense option for the Maps it produces.
  • DirCopy extracts .zip, .tar, .tar.gz and .tgz archives, and decompresses a plain .gz.
  • Array.Remove returns whether it removed anything, and Contains, IndexOf and Remove search for an element with no value when Value is omitted.
  • SplitPath returns an object with FileName, Dir, Extension, NameNoExt and Drive properties when every output variable is omitted, as in SplitPath(Path).Dir.
  • File.Read takes an optional character count; omitting it reads the rest of the stream.
  • FileEncoding and its siblings accept any encoding .NET recognizes, such as windows-1252.
  • #Import accepts a relative path. Bare imports and aliases bind module objects, and imported names are forwarded only by #Import Export. A backslash works as a path separator on every platform in #Include, #Import and #CSharp.
  • The EventHook class is the base of every event subscription — WinEvent, Monitor.OnChange, Clipboard.OnChange, Audio.OnDeviceChange, CLR events and InputHook — with Start, Stop, InProgress and EndReason. WinEvent, Monitor, Clipboard, Audio and Clr each list their running hooks in a static Hooks property. See Lifetime and Keeping the Script Running.
  • OnEvent subscribes a script function to an event of a .NET object or type.
  • Clr accepts an Integer where a .NET enum is expected, including undeclared flag combinations.
  • A Buffer passed where .NET expects a byte[], through Clr or #CSharp, arrives as a copy of its bytes.
  • Gui, Gui.Control, Menu, Http and Http.Response, Image, Task, and Audio.Device and Audio.Session return the .NET object behind them from ToClr(), and Clr.Wrap returns any value as a Clr object. A CLR API declaring an IDictionary<object, object> or IList accepts a Map or Array directly. Inline C# reads the raw object behind a Clr wrapper from its Native property.

Fixes and Performance

An AStr return value is read and left to the function which returned it, and a null Str or AStr return value is an empty string, as in AutoHotkey. A variable holding a number, given a Str argument, passes the number's string form, as in AutoHotkey.

Creating an object, Array, Map or VarRef is faster. Only an Object, or a Struct which owns its memory, is given a __Delete call, as in AutoHotkey: a VarRef, ComValue, Module or prototype is not, whatever defines it, and neither is a Struct created as a view of other memory, such as by Struct.At, through a pointer or nested field, or as an array element.

A __Delete method can read the memory of its Buffer or Struct and write to its File, and so can one of an object holding them, since what is collected with an object is freed only after its __Delete returns. An object which __Delete stores stays usable. At exit, global and static variables are released, as in AutoHotkey, so an object held in an Array or another object is also given its __Delete, and a File in one is flushed and closed. Every other File still open is flushed, as in AutoHotkey.

Clone gives the clone its own copy of each own property, so assigning or defining a property on one leaves the other unchanged, and a Buffer or StringBuffer its own copy of the memory. Cloning another object of a built-in type which holds a native resource, such as a File, Http session or ScriptProcess, raises a TypeError, as in AutoHotkey.

A Str* or AStr* argument whose pointer the function leaves alone leaves the variable as it was, as in AutoHotkey.

A StringBuffer's memory is freed when it is collected, and a negative capacity raises a ValueError.

The code of an Exit in a launched thread which leaves the script running is not used by a later automatic exit, as in AutoHotkey, and a run-once timer does not count as keeping the script running while its own thread runs.

Send restoring stale modifiers in SendEvent mode, #Warn reporting the wrong line in an included file, #Import creating a setter for a read-only property, overriding a built-in class's __Enum, continuation sections, switch and Loop Files condition parsing, and a leading comma in a function call statement. Send {Click X Y Count} moves the pointer once before repeating the click, successful output operations store a blank value when no result exists, and a ListView column-header ContextMenu event reports Item as 0. A_MyDocuments, A_Desktop and the A_*Common folders resolve correctly. GUI fixes cover addressing a control by ClassNN, xs/ys anchoring in Tab3 pages, measuring a control created hidden, and a checkbox reporting its own state. A fat-arrow function reads a property exactly as a block-bodied one does; a call or an index in an arrow body propagates an unset result. A script read from standard input resolves #Include against the working directory, which is what A_ScriptDir reports for it, and a byte-order mark at the head of such a script is not read as code. A wildcard import such as #Import Ks { * } makes every name the module exports available in any module of the script, dynamic references included, whether or not the importing code names it. Of two wildcard imports which supply a name, the later one takes precedence. A class definition extends a class declared in another module through any import of it or through that module's object, as in class Item extends Other.Outer.Item. A class nested in another class is named by its full dotted path, as in AutoHotkey: Type and Prototype.__Class report Gui.Text for a text control, Clr.ManagedType, and Outer.Inner for a script's own nested class, each of which reported only the short name. Type names an instance of a class which declares no fields by its class. A nested class is reached only through the class which declares it, so Audio.%"Device"% is the dynamic form and the bare %"Device"% is an undefined name. The right operand of is must be a class, and anything else throws a TypeError reading Expected a Class but got a String; for a class named at run time, write x is %"Array"%. Through an assembly Clr.Load returns, a namespace the assembly declares is found before a same-named type from another assembly, so Clr.Load("System.Net.Http").System.Net.Http reaches the namespace on macOS. #HotIf criteria are evaluated faster. InputHook.Wait can be called without an argument, InputHook.EndReason reads an empty string while an input is in progress, InputHook.EndKey reads an empty string when the input did not end by an end key, and assigning unset to an InputHook callback property clears it, as in AutoHotkey. A script exits once nothing keeps it running and its last thread finishes, as in AutoHotkey, including when an InputHook which kept it running ends or a thread calls Persistent(false).

Reading a property walks past an own property which cannot produce one — a setter without a getter, or a Call where something further up the chain has a value — so an inherited value, method or __Get is reached as it is in AutoHotkey, and a setter is never returned as a method. A name nothing in the chain has raises a PropertyError naming the value's type, where it previously raised the more general UnsetError; PropertyError is an UnsetError, so an existing catch UnsetError is unaffected. ObjHasOwnProp handed a string or number raises a TypeError.

A number keeps a trailing . when what follows it cannot begin a member name, so 1. is the float 1.0 and the operand beside it concatenates — 1. 2 is "1.02", matching AutoHotkey — while 1.Foo and 1 .2 stay member accesses on the integer. An inline block comment is whitespace to every decision that looks backwards: a :: inside one is comment text rather than a hotkey separator, so a line such as x := 1 /* a :: b */ compiles, and a comment before a . leaves it a member access. A class field initializer needing a temporary, such as x := (this.arr[1] += 5), compiles. A line which begins with a continuation operator is merged with the line above it whatever that line is, as in AutoHotkey, so a name alone on its line, such as MsgBox followed by a line .Call("Hi"), and a Return are continued by it, and a trailing comma continues a function call statement's parameters onto the next line.

A built-in which takes a callback — SetTimer, Hotkey, OnMessage, OnClipboardChange, OnExit, a GUI or menu event, an InputHook callback property or an event hook — accepts any object with a Call method, as AutoHotkey does, and also, unlike AutoHotkey, one with only a __Call method, which it is called through, and a callback property or A_HotIf gives back the object which was assigned. RegExReplace takes such an object as its Replacement. A Menu item given a new callback runs only that one, Hotstring takes a number as replacement text, and HotIfWinActive and its siblings called again with the same window select the same criterion, so a hotkey defined under either is the same variant, while a blank title and text select none. A hotkey or hotstring defined under one of them has its window checked again when the script receives it, as in AutoHotkey, so it does not run once that window is no longer active or no longer exists; a hotstring's Last Found Window is the window which matched, and the Not forms set none. A Menu item made a submenu stops running the callback it had. Sort raises the first error its callback raises, once, as AutoHotkey does, where every comparison raised it and the sort went on. Calling an object which has no Call raises a MethodError, and a COM object called as a function invokes its default member, as in AutoHotkey. HasProp returns 0 for an object whose base has no own properties.

A ContextMenu event runs the control's callbacks and then, unless one of them returns a non-empty value, the window's, which receive that control as GuiCtrlObj, as in AutoHotkey, for a right-click, Menu and Shift+F10 alike. IsRightClick is 1 only for a right-click. On Windows, Item, X and Y are those AutoHotkey reports, such as the right-clicked ListView row and, for a key, the position of the focused item.

A StringBuffer handed to Base64.Encode or to a Crypt method is taken as its text, the same as the equivalent string.

An OnError callback which another callback removes while an error is being handled is not called for that error, as in AutoHotkey. Throw, the statement and the function alike, takes a value of any kind and throws one which is not an Error as Error(Value); an object's Message property supplies the wrapper's message.

The global OnMessage callbacks are called once for each message, including one whose callback waits, such as with Sleep, and one identical to a message they claimed.

A thread which interrupts another starts outside that thread's loops and Try statements, as in AutoHotkey: its A_Index is 0 and its loop variables describe only its own loops, assigning A_Index leaves the interrupted loop's count unchanged, outside a loop A_Index keeps the value the thread assigns it, and an error nothing in it catches reaches the OnError callbacks even while the interrupted thread is inside a Try.

A ByRef parameter reached through %name% or from a nested function is the caller's variable, which is read, assigned and referenced through it, and reading one whose variable has no value raises This parameter has not been assigned a value. A global which a nested function declares is that global even where an enclosing function has a local of the same name. A nested function or fat-arrow function is a closure only when it, or a function within it, uses a local variable of an enclosing function or refers to another closure, as in AutoHotkey. Any other is static, so each call of the enclosing function gives the same function, and passing it to SetTimer again updates the one timer. A nested function or named fat-arrow function whose name a parameter, a declaration or another function of the same function already has is a load-time error, as in AutoHotkey. #Warn VarUnset warns of a read of a global which a function declares but nothing assigns, and not of a global which a function assigns.

A loop's Else runs only when the loop completes without an iteration, never when an error ends the loop, and may use Return, or Break and Continue for an enclosing loop. %name% += Value, ++%name% and %name%++ find their variable once and evaluate the right operand before reading it, and %name% ??= Value finds its variable once and evaluates Value only when the variable has no value, as in AutoHotkey. A_Args takes any value a script assigns it, unset included, by name, through %name% or a reference, or as AHK.A_Args, as in AutoHotkey, where it could not be assigned. An UnsetError for a module variable read through a module object, and ListVars, name the variable as it is declared.

An ActiveX control's value is its COM object, and ComObjQuery returns a dispatch object. A ComObjConnect event handler runs inside the call which raised the event, as in AutoHotkey, so it can read state which lasts only for that call, such as an HTML document's window.event, and its return value and any error it raises go back to the COM object; an Exit there ends only the handler. Gui.Opt changes an existing window in place, so its Hwnd stays the same through +Owner and +ToolWindow, and a window with -Caption +Resize keeps its sizing border. An owner given when the window is created is kept, -Owner removes the owner, a window which does not exist raises a ValueError, and an explicit +E0x40000 gives an owned or tool window its taskbar button. Loop Parse without OmitChars keeps white space, and visits every empty field. #Warn LocalSameAsGlobal warns only of an undeclared local, including one a compound assignment makes, and compares it with every global name, the script's functions and classes and the built-in ones included, as in AutoHotkey.

A GUI's margins are in the units of a control's position at any DPI, as in AutoHotkey: MarginX and MarginY are scaled by the window's DPI when assigned and read, the default margins are 1.25 and 0.75 times the font's point size, and x+m and y+m add the margin to a number which follows them. On Windows, a GUI's controls are children of the GUI window, as in AutoHotkey, and the notifications they send it, such as an Edit's EN_CHANGE, reach an OnMessage callback for WM_COMMAND; with a menu bar they are children of a panel below it, as that section describes. MyGui.MenuBar := "" removes the menu bar, a value which is not a MenuBar raises a TypeError, assigning or removing a menu bar leaves the window its size, and the margins, the section and the positions of the controls are the same with a menu bar as without one.

A script object given to a COM client, such as a function or a class instance passed to the script of an HTML page, is used as in AutoHotkey. Its members are found whatever the case of the name the client uses, a built-in one such as an Array's Push included; a name which only __Call or __Get answers for is called or read, and assigning a name the object does not have creates the property. A function called as a member of one of the client's objects receives only the arguments it was passed, and an object of the client's arrives as a ComObject. A client which enumerates the object, as VBScript's For Each and JScript's Enumerator do, receives the first variable of each item of its __Enum. True is returned as 1, an error the script raises reaches the client with its message, and a name the object has no member for is reported as not found. A script object which a COM object gives back is that object rather than a ComObject wrapping it, and an ObjBindMethod object can be given to a COM client as a callback.

Reading or writing a COM object's property, like calling its method, consults the object's type information only when the object rejects an argument, which makes working with the elements of an HTML document many times faster. An object is assigned by reference and, failing that, by value, as in AutoHotkey; ComObj.Prop[Index] indexes the property's value when the property takes no parameters of its own; a member which takes a variable number of arguments is passed each one as it is given; and assigning a boolean through a ComValue reference to a variant stores 1 or 0. With the A option, RegExMatch and RegExReplace anchor the match at StartingPos, as in AutoHotkey, where it was anchored at the start of Haystack. Format's 0 flag pads a string or a character with zeros, as in AutoHotkey, so Format("{:02}", 9) is 09. DateAdd and DateDiff raise a ValueError for a timestamp which is not valid, as Array.RemoveAt does for an index outside the array, an empty array's included. A callback which a window message calls, and an event handler which a COM object calls, check for messages only once the message-check interval has passed within them, as in AutoHotkey.
